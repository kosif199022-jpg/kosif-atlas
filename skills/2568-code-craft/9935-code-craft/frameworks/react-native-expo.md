# React Native + Expo — code-craft reference

~50 rules across three buckets, native-mobile-specific. React-general rules (hooks, components, JSX, RSC) live in `frameworks/react.md` — do not repeat them. Assumes Expo SDK 53/54+ with the New Architecture (Fabric + TurboModules) on by default, Expo Router v3+/v4, Hermes, and TypeScript. Bare RN CLI users can ignore Expo-only rules; everything else still applies.

Sources: [docs.expo.dev](https://docs.expo.dev), [reactnative.dev](https://reactnative.dev), [Expo SDK 54 changelog](https://expo.dev/changelog/sdk-54), [React Native 0.82 — A New Era](https://reactnative.dev/blog/2025/10/08/react-native-0.82), Evan Bacon on Expo Router, [Shopify on FlashList v2](https://shopify.engineering/flashlist-v2), Margelo (reanimated, MMKV, op-sqlite), William Candillon on Skia, Software Mansion (gesture-handler, reanimated).

Loaded by `code-craft` when the user asks about React Native / Expo or pastes RN code for review.

## A — Tactical (day-to-day patterns)

### A1. File-based routing with Expo Router
**Rule.** Use Expo Router (`app/` directory, file-based) over hand-rolled `react-navigation` config.
**Reason.** Routes become URLs, deep links work for free, typed routes and protected layouts are first-class.
```tsx
// app/_layout.tsx
import { Stack } from 'expo-router';
export default function RootLayout() { return <Stack />; }
// app/(tabs)/_layout.tsx → Tabs; app/[id].tsx → dynamic; app/(auth)/login.tsx → group
```

### A2. `_layout.tsx` per route group
**Rule.** Each segment that needs its own navigator (Stack, Tabs, Drawer) gets a `_layout.tsx`.
**Reason.** Layouts compose; nested layouts inherit context and headers without prop drilling.
```tsx
// app/(tabs)/_layout.tsx
import { Tabs } from 'expo-router';
export default function TabsLayout() {
  return <Tabs screenOptions={{ headerShown: false }} />;
}
```

### A3. Route groups for organization without URL impact
**Rule.** Use `(group)` parens to organize files without affecting the URL — `(auth)/login.tsx` is `/login`.
**Reason.** Lets you split auth, tabs, modals into folders without nested URLs.
```tsx
// app/(auth)/login.tsx → URL is /login, not /auth/login
// app/(tabs)/home.tsx → URL is /home, layout is the tab bar
```

### A4. Dynamic routes with `[param]`
**Rule.** Read params with `useLocalSearchParams<T>()`, not from a `useState` you set on mount.
**Reason.** Router is the source of truth; deep links and back/forward set params for free.
```tsx
// app/posts/[id].tsx
import { useLocalSearchParams } from 'expo-router';
const { id } = useLocalSearchParams<{ id: string }>();
```

### A5. Typed routes
**Rule.** Enable `experiments.typedRoutes: true` in `app.json` and rely on the autogenerated `Href` type.
**Reason.** `<Link href="/typo">` becomes a compile error; refactors are safe. ([Expo typed routes](https://docs.expo.dev/router/reference/typed-routes/))
```ts
// app.json
{ "expo": { "experiments": { "typedRoutes": true } } }
// usage
<Link href={{ pathname: '/posts/[id]', params: { id: post.id } }} />
```

### A6. `router.push` / `replace` over imperative nav stacks
**Rule.** Use `useRouter()` from `expo-router`; reserve `replace` for post-auth redirects so back doesn't return to login.
**Reason.** Matches web mental model, plays nicely with deep links, no manual nav refs.
```tsx
const router = useRouter();
router.push('/posts/42');           // pushes
router.replace('/(tabs)/home');     // post-login, no back-to-login
```

### A7. Deep links via `expo-linking` + `scheme`
**Rule.** Set `scheme` in `app.json`, build URLs with `Linking.createURL`, and validate with `Linking.canOpenURL` before opening external URLs.
**Reason.** Prevents crashes on devices missing the target app and centralizes scheme config.
```ts
import * as Linking from 'expo-linking';
const url = Linking.createURL('/posts/42'); // myapp://posts/42
if (await Linking.canOpenURL(externalUrl)) await Linking.openURL(externalUrl);
```

### A8. `StyleSheet.create` (or NativeWind) — never inline in lists
**Rule.** Define styles via `StyleSheet.create` outside the component, or use NativeWind v4 `className`. Never object-literal styles inside `renderItem`.
**Reason.** Inline styles allocate per render; in long lists this tanks scroll FPS.
```tsx
// wrong
<FlatList renderItem={({item}) => <View style={{padding: 12}}>...</View>} />
// right
const styles = StyleSheet.create({ row: { padding: 12 } });
<FlatList renderItem={({item}) => <View style={styles.row}>...</View>} />
```

### A9. Flexbox defaults differ from web
**Rule.** Remember `flexDirection` defaults to `'column'`, `alignItems` to `'stretch'`, and `flex: 1` does not behave like CSS `flex: 1 1 auto`.
**Reason.** Web habits cause silent layout bugs in RN.
```tsx
// row layout requires explicit direction
<View style={{ flexDirection: 'row', alignItems: 'center', gap: 8 }}>...</View>
```

### A10. `FlashList` for big virtualized lists, `FlatList` for small
**Rule.** Use `@shopify/flash-list` v2 for any list >100 items or with images; reach for `FlatList` only for short, simple lists. Never `.map()` hundreds of children.
**Reason.** FlashList v2 was rewritten for the New Architecture — no more `estimatedItemSize`, better recycling, 60 FPS at scale. ([Shopify](https://shopify.engineering/flashlist-v2))
```tsx
import { FlashList } from '@shopify/flash-list';
<FlashList data={items} renderItem={renderRow} keyExtractor={(i) => i.id} />
```

### A11. `keyExtractor` always
**Rule.** Provide `keyExtractor` returning a stable string id — never the index.
**Reason.** Index keys cause stale cells, animation glitches, and the dreaded "duplicate key" warning.
```tsx
<FlatList data={items} keyExtractor={(item) => item.id} renderItem={...} />
```

### A12. `getItemLayout` for fixed-height rows
**Rule.** When every row is the same height, supply `getItemLayout` (FlatList) — FlashList v2 handles this automatically.
**Reason.** Skips measure pass; dramatic improvement on initial render and `scrollToIndex`.
```tsx
const ITEM_H = 64;
<FlatList getItemLayout={(_, i) => ({ length: ITEM_H, offset: ITEM_H * i, index: i })} ... />
```

### A13. `expo-image`, not core `<Image>`
**Rule.** Use `expo-image`'s `<Image>` everywhere — set `placeholder` (blurhash or thumbhash), `contentFit`, and `transition`.
**Reason.** Core RN `Image` has unreliable HTTP-header caching and blocks the UI thread on resize; `expo-image` caches to memory + disk and animates transitions for free.
```tsx
import { Image } from 'expo-image';
<Image source={url} placeholder={{ blurhash }} contentFit="cover" transition={200} />
```

### A14. `expo-secure-store` for tokens, MMKV for everything else, AsyncStorage as legacy
**Rule.** Auth tokens / PII → `expo-secure-store` (Keychain/Keystore). Hot key-value → `react-native-mmkv` (~30× faster, sync). AsyncStorage only if you can't drop it.
**Reason.** SecureStore is hardware-backed; MMKV is memory-mapped and synchronous, so reads don't block on a Promise round-trip.
```ts
import * as SecureStore from 'expo-secure-store';
import { MMKV } from 'react-native-mmkv';
await SecureStore.setItemAsync('jwt', token);  // never AsyncStorage for tokens
const kv = new MMKV();
kv.set('lastSeenPostId', '42');                // sync, instant
```

### A15. Connectivity via `expo-network`, data via TanStack Query
**Rule.** Use `expo-network` (or `@react-native-community/netinfo`) for online/offline events; let TanStack Query handle fetching, caching, retries, and focus refetch.
**Reason.** Manual `useEffect` fetch loops re-implement (badly) what Query already gives you, plus offline persistence via `persistQueryClient`.
```ts
import { useNetworkState } from 'expo-network';
const { isInternetReachable } = useNetworkState();
// then use useQuery with enabled: !!isInternetReachable for offline-aware fetches
```

### A16. Just-in-time permission asks
**Rule.** Request camera, location, contacts, notifications at the moment the user taps the feature — never at app launch.
**Reason.** iOS denies you twice if you spam-ask on first launch; just-in-time wording converts better and is App Store guideline.
```tsx
import * as ImagePicker from 'expo-image-picker';
async function onAttachPhoto() {
  const { status } = await ImagePicker.requestMediaLibraryPermissionsAsync();
  if (status !== 'granted') return showRationale();
  /* ... */
}
```

### A17. `react-native-keyboard-controller` over `KeyboardAvoidingView`
**Rule.** For non-trivial keyboard-aware screens, use `react-native-keyboard-controller`'s `KeyboardAvoidingView` / `KeyboardAwareScrollView` instead of core RN.
**Reason.** Core `KeyboardAvoidingView` behaves differently per platform and frequently misses; the library uses native keyboard frame events for smooth, consistent animations on both OSes. ([RNKC](https://kirillzyusko.github.io/react-native-keyboard-controller/))
```tsx
import { KeyboardAvoidingView } from 'react-native-keyboard-controller';
<KeyboardAvoidingView behavior="padding" style={{ flex: 1 }}>...</KeyboardAvoidingView>
```

### A18. `useSafeAreaInsets` for notches and home indicators
**Rule.** Wrap the app in `<SafeAreaProvider>` once; use `useSafeAreaInsets()` per screen. Never hardcode `paddingTop: 44`.
**Reason.** Inset values vary per device and orientation; hardcoding breaks on the next iPhone.
```tsx
const insets = useSafeAreaInsets();
<View style={{ paddingTop: insets.top, paddingBottom: insets.bottom }} />
```

### A19. `expo-status-bar` with `style="auto"`
**Rule.** Use `<StatusBar style="auto" />` from `expo-status-bar`; let it follow the color scheme.
**Reason.** Manual `light`/`dark` becomes wrong the moment the user toggles dark mode.
```tsx
import { StatusBar } from 'expo-status-bar';
<StatusBar style="auto" />
```

### A20. Dark mode with `useColorScheme` + persisted override
**Rule.** Read system theme via `useColorScheme()`; let users override and persist that choice in MMKV.
**Reason.** Many users want a hard preference; system-only ignores them.
```tsx
const system = useColorScheme();
const override = kv.getString('theme') as 'light' | 'dark' | undefined;
const theme = override ?? system ?? 'light';
```

### A21. Platform-specific code via `Platform` and file extensions
**Rule.** For one-liners use `Platform.OS` / `Platform.select`; for whole modules use `.ios.tsx` / `.android.tsx` / `.web.tsx`.
**Reason.** Metro picks the right file automatically; cleaner than giant `if` ladders.
```tsx
// Button.ios.tsx, Button.android.tsx — same export
const offset = Platform.select({ ios: 0, android: 24, default: 0 });
```

### A22. `useWindowDimensions` over `Dimensions.get`
**Rule.** Read screen size with the `useWindowDimensions()` hook; don't read `Dimensions.get('window')` once at module load.
**Reason.** Module-load reads don't update on rotate, split-screen, or foldables.
```tsx
// wrong
const { width } = Dimensions.get('window');
// right
const { width } = useWindowDimensions();
```

### A23. Hermes is the default engine; debug with React DevTools
**Rule.** Keep Hermes on (default since 2023); inspect via React DevTools and the in-app Dev Menu — the legacy "Remote JS Debugger" is gone.
**Reason.** Hermes starts fast, ships smaller bytecode, and is required for the New Architecture's full perf story.
```ts
// app.json — usually leave alone (default true). Don't disable for "JSI compat" without measuring.
{ "expo": { "jsEngine": "hermes" } }
```

### A24. `expo-font` with `useFonts` + held splash
**Rule.** Hold the splash screen until `useFonts` resolves, then `SplashScreen.hideAsync()`.
**Reason.** Otherwise users see a flash of system font, then a re-layout when custom fonts load.
```tsx
SplashScreen.preventAutoHideAsync();
const [loaded] = useFonts({ Inter: require('./Inter.ttf') });
useEffect(() => { if (loaded) SplashScreen.hideAsync(); }, [loaded]);
if (!loaded) return null;
```

### A25. `Pressable` over `TouchableOpacity`
**Rule.** Reach for `<Pressable>` as the default touch primitive; reserve `TouchableOpacity` for trivial cases where the default opacity dimming is fine.
**Reason.** RN docs themselves recommend `Pressable` going forward — style-as-function gives you `pressed`/`hovered`/`focused` states without wrapper layers.
```tsx
<Pressable
  style={({ pressed }) => [styles.btn, pressed && { opacity: 0.6 }]}
  onPress={onSubmit}
  accessibilityRole="button"
  accessibilityLabel="Submit form"
>
  <Text>Submit</Text>
</Pressable>
```

### A26. Accessibility props on every custom touchable
**Rule.** `accessibilityRole`, `accessibilityLabel`, and (when stateful) `accessibilityState` on anything tappable that isn't a built-in `Button`.
**Reason.** VoiceOver/TalkBack users get nothing useful from a bare `View`; App Store reviewers also flag this.
```tsx
<Pressable accessibilityRole="switch" accessibilityState={{ checked: on }} onPress={toggle}>
  ...
</Pressable>
```

## B — Modern Expo / RN idioms

### B1. New Architecture is on — don't fight it
**Rule.** Treat Fabric + TurboModules as the default; on SDK 53/54 it's already enabled, on SDK 55+ it can't be turned off. Drop libraries that aren't NA-compatible.
**Reason.** Concurrent rendering, synchronous layout effects, and JSI modules all assume NA. The legacy bridge is gone in 0.82+. ([RN 0.82 announcement](https://reactnative.dev/blog/2025/10/08/react-native-0.82))
```ts
// app.json on SDK 54: leave default (true). On SDK 55+, remove the key entirely.
{ "expo": { "newArchEnabled": true } }
```

### B2. Protected route groups via `Stack.Protected`
**Rule.** Gate authenticated areas with `<Stack.Protected guard={!!session}>` rather than `useEffect` redirects.
**Reason.** Declarative, deep-link-safe, no race between mount and redirect. Protected screens are client-side gating only — still authenticate on the server. ([Expo: protected routes](https://docs.expo.dev/router/advanced/protected/))
```tsx
// app/_layout.tsx
<Stack>
  <Stack.Protected guard={!!session}>
    <Stack.Screen name="(tabs)" />
  </Stack.Protected>
  <Stack.Protected guard={!session}>
    <Stack.Screen name="(auth)" />
  </Stack.Protected>
</Stack>
```

### B3. `app.config.ts` for dynamic config
**Rule.** Use `app.config.ts` (TypeScript) when bundle id, name, icons, or env keys differ per profile. Plain `app.json` only for fully static config.
**Reason.** Lets you read `process.env.APP_VARIANT` at config time and switch bundle id between dev/preview/prod.
```ts
// app.config.ts
export default ({ config }) => ({
  ...config,
  ios: { bundleIdentifier: process.env.APP_VARIANT === 'prod' ? 'com.acme' : 'com.acme.dev' },
});
```

### B4. EAS Build profiles: `development`, `preview`, `production`
**Rule.** Keep the three default profiles in `eas.json`; map them to dev clients, ad-hoc/internal builds, and store builds respectively.
**Reason.** Standard names integrate with EAS Update channels and EAS env vars. ([EAS profiles](https://docs.expo.dev/build/eas-json/))
```json
// eas.json (excerpt)
{ "build": {
  "development": { "developmentClient": true, "distribution": "internal" },
  "preview":     { "distribution": "internal" },
  "production":  {}
}}
```

### B5. EAS environment variables per profile
**Rule.** Store secrets and per-env public values in EAS environments (development/preview/production); read them via `process.env.EXPO_PUBLIC_*` at build time.
**Reason.** Prevents prod builds shipping with staging API URLs; `EXPO_PUBLIC_` is the only prefix Metro inlines.
```ts
const apiUrl = process.env.EXPO_PUBLIC_API_URL!; // baked in at build, per profile
```

### B6. EAS Update for OTA JS-bundle pushes
**Rule.** Use `eas update --channel production` for JS/asset-only fixes; only rebuild + resubmit when native code or config changes.
**Reason.** Skips store review, reaches users instantly. Channels typically map 1:1 with build profiles.
```bash
eas update --channel production --message "fix crash on /posts/[id]"
```

### B7. EAS Submit for store delivery
**Rule.** `eas submit --profile production --platform all` after a successful build; configure `submit.production` once.
**Reason.** Hands off to App Store Connect / Google Play API without local Xcode/Android dance.

### B8. `expo-dev-client` for native modules in dev
**Rule.** Install `expo-dev-client` on any project that uses libraries with native code (camera, MMKV, reanimated, gesture-handler) — never eject just to add a native module.
**Reason.** Gives you a dev launcher that loads JS from Metro into a custom native binary; ejecting throws away managed-workflow benefits.

### B9. Reanimated v3+ over the legacy `Animated` API
**Rule.** Use `useSharedValue` + `useAnimatedStyle` (worklets on the UI thread) for any non-trivial animation.
**Reason.** Legacy `Animated` runs on the JS thread and stutters under load; reanimated worklets run native and stay 60 FPS during scroll. ([Software Mansion](https://docs.swmansion.com/react-native-reanimated/))
```tsx
const x = useSharedValue(0);
const style = useAnimatedStyle(() => ({ transform: [{ translateX: x.value }] }));
return <Animated.View style={style} />;
```

### B10. `react-native-gesture-handler` for gestures
**Rule.** Replace `PanResponder` and raw touch events with `Gesture` from `react-native-gesture-handler`; compose with reanimated shared values.
**Reason.** Handlers run on the UI thread, don't fight the scroll view, and survive fast finger flicks.
```tsx
const pan = Gesture.Pan().onUpdate(e => { x.value = e.translationX; });
<GestureDetector gesture={pan}><Animated.View style={style} /></GestureDetector>
```

### B11. Charts / vector art via Skia or react-native-svg
**Rule.** For charts, prefer `victory-native` (Skia-backed) or hand-rolled `@shopify/react-native-skia`; for static SVG illustrations, `react-native-svg`.
**Reason.** Skia draws on the GPU and stays smooth at 60 FPS even with thousands of points; SVG is fine for icons/illustrations but slow for animated charts.

### B12. `expo-notifications`: handler, channels, categories
**Rule.** Set `Notifications.setNotificationHandler` once; create Android channels at startup; declare iOS categories for actionable notifications.
**Reason.** Without a handler, foreground notifications are silently dropped on iOS; without channels, Android 8+ ignores you.
```ts
Notifications.setNotificationHandler({
  handleNotification: async () => ({ shouldShowBanner: true, shouldPlaySound: true, shouldSetBadge: false }),
});
await Notifications.setNotificationChannelAsync('default', { name: 'default', importance: Notifications.AndroidImportance.DEFAULT });
```

### B13. Push tokens belong on the server, not in AsyncStorage
**Rule.** Send the Expo Push Token to your backend, keyed by user id; don't cache it in AsyncStorage as user PII.
**Reason.** Tokens rotate; the server's DB is the source of truth. Storing locally invites stale-token bugs and PII leakage.
```ts
const { data: token } = await Notifications.getExpoPushTokenAsync({ projectId });
await api.registerPushToken(userId, token);
```

### B14. `expo-haptics`, respecting reduced motion
**Rule.** Trigger short haptics on success/error/swipe; check `AccessibilityInfo.isReduceMotionEnabled()` before chaining haptic + animation.
**Reason.** Heavy haptics on reduce-motion users is hostile; subtle pulses are great UX otherwise.
```ts
import * as Haptics from 'expo-haptics';
Haptics.notificationAsync(Haptics.NotificationFeedbackType.Success);
```

### B15. Splash handover: prevent → load → hide
**Rule.** Call `SplashScreen.preventAutoHideAsync()` early, then `hideAsync()` after fonts/data are ready.
**Reason.** Avoids "blank screen" flicker between native splash and first JS frame.
```ts
SplashScreen.preventAutoHideAsync();
// in root layout, after critical async init:
await SplashScreen.hideAsync();
```

### B16. Forms with `react-hook-form` + `Controller`
**Rule.** Wrap RN inputs in `<Controller>`; use `KeyboardAwareScrollView` from keyboard-controller for the screen container.
**Reason.** RHF avoids re-rendering every input on each keystroke; controllers bridge uncontrolled native inputs into RHF's value system.
```tsx
<Controller control={control} name="email" render={({ field }) => (
  <TextInput value={field.value} onChangeText={field.onChange} />
)} />
```

### B17. Date pickers via `@react-native-community/datetimepicker`
**Rule.** Use the native datetimepicker on iOS/Android; ship a web fallback (`<input type="date">`) for web.
**Reason.** Custom JS date wheels feel off on both platforms; native pickers respect system locale and a11y.

### B18. `expo-file-system` — cache vs document directory
**Rule.** Put downloaded thumbnails / temp files in `cacheDirectory`; user-saved data in `documentDirectory`. Clean caches on a TTL.
**Reason.** iOS may evict `cacheDirectory` under storage pressure; `documentDirectory` is backed up and persistent.
```ts
import * as FileSystem from 'expo-file-system';
const target = FileSystem.cacheDirectory + 'thumbs/' + id + '.jpg';
```

### B19. SQLite via `expo-sqlite` (modern API) or `op-sqlite`
**Rule.** Default to `expo-sqlite`'s modern hook-based API (`useSQLiteContext`, `withTransactionAsync`, prepared statements). Reach for `op-sqlite` only when you've measured a JSI bottleneck.
**Reason.** `expo-sqlite` gives you transactions + web support for free; `op-sqlite` is faster but adds bare-RN-style native config and no web target.
```tsx
const db = useSQLiteContext();
await db.withTransactionAsync(async () => {
  await db.runAsync('UPDATE posts SET seen = 1 WHERE id = ?', id);
});
```

### B20. Sharing & PDF via `expo-sharing` / `expo-print`
**Rule.** Generate PDFs from HTML with `expo-print`, then hand the URI to `expo-sharing`.
**Reason.** Skips native PDF libraries; the native share sheet handles AirDrop, email, drive, etc.
```ts
const { uri } = await Print.printToFileAsync({ html });
await Sharing.shareAsync(uri);
```

### B21. `@expo/vector-icons` over `react-native-vector-icons`
**Rule.** Import icons from `@expo/vector-icons` (pre-bundled, no font-loading dance) — not `react-native-vector-icons`.
**Reason.** `@expo/vector-icons` ships fonts as assets and works with EAS Build out of the box; the legacy package needs Podfile / `gradle` edits.
```tsx
import { Ionicons } from '@expo/vector-icons';
<Ionicons name="heart" size={20} />
```

### B22. Background work via `expo-background-fetch` / `expo-task-manager`
**Rule.** Use `expo-background-fetch` (with `expo-task-manager`) for periodic background sync; do not poll with `setInterval`.
**Reason.** OS suspends JS when backgrounded — your interval simply stops. TaskManager wakes the app on the OS's schedule.

### B23. Modals as `expo-router` modal routes
**Rule.** Declare modals in the router (`presentation: 'modal'`), not as sibling components toggled with state.
**Reason.** Router modals participate in deep linking, back-button handling, and animation chrome the OS provides.
```tsx
// app/_layout.tsx
<Stack>
  <Stack.Screen name="post-modal" options={{ presentation: 'modal' }} />
</Stack>
```

### B24. `__DEV__` guard for dev-only logs
**Rule.** Wrap `console.log` in `if (__DEV__)` or use a logger with a production no-op build.
**Reason.** Console calls in production hurt JS perf and leak app internals; `__DEV__` is dead-code-eliminated by Hermes.
```ts
if (__DEV__) console.log('debug', payload);
```

## D — Anti-patterns / smells

### D1. Core `<Image>` for remote URLs
**Smell.** `import { Image } from 'react-native'` for network images.
**Why bad.** Unreliable cache, UI-thread blocking, no placeholder.
```tsx
// wrong
<Image source={{ uri }} style={{ width: 100, height: 100 }} />
// right
import { Image } from 'expo-image';
<Image source={uri} placeholder={blurhash} contentFit="cover" />
```

### D2. Inline styles inside `renderItem`
**Smell.** Object literals in list rows.
**Why bad.** New object every render → cell re-mount on scroll → frame drops.
```tsx
// wrong
renderItem={({item}) => <View style={{padding: 12, backgroundColor: '#fff'}}>...
// right — hoist to StyleSheet
```

### D3. AsyncStorage for tokens or PII
**Smell.** `AsyncStorage.setItem('jwt', ...)`.
**Why bad.** Plaintext on disk, world-readable on rooted devices; Apple/Google guidelines require Keychain/Keystore.
```ts
// wrong
AsyncStorage.setItem('jwt', token);
// right
SecureStore.setItemAsync('jwt', token);
```

### D4. AsyncStorage as a database
**Smell.** Storing arrays of hundreds of records as one JSON blob in AsyncStorage.
**Why bad.** Sync read/parse blocks the JS thread; AsyncStorage is key-value, not a DB. Use SQLite or MMKV (with discrete keys).

### D5. Heavy work on the JS thread
**Smell.** Tight loops, big `JSON.parse`, image decode in a `useEffect`.
**Why bad.** Blocks render and animations. Move to reanimated worklets, `InteractionManager.runAfterInteractions`, or a background task.

### D6. `.map()` rendering for big lists
**Smell.** `{items.map(i => <Row {...i} />)}` for hundreds of rows inside a `ScrollView`.
**Why bad.** Mounts every row on entry — no virtualization, no recycling.
```tsx
// wrong
<ScrollView>{items.map(i => <Row key={i.id} {...i} />)}</ScrollView>
// right
<FlashList data={items} renderItem={renderRow} keyExtractor={i => i.id} />
```

### D7. Missing `keyExtractor` / index keys
**Smell.** Relying on default keying or `keyExtractor={(_, i) => i.toString()}`.
**Why bad.** Reorders break, animations glitch, dev warnings about key collisions.

### D8. No `getItemLayout` for fixed-height rows
**Smell.** `FlatList` of 1000 fixed-height items with no `getItemLayout`.
**Why bad.** Every measure pass is JS work; `scrollToIndex` becomes janky.

### D9. Hardcoded notch insets
**Smell.** `paddingTop: 44` for iPhone notch.
**Why bad.** Wrong on Android, wrong on every new iPhone, wrong in landscape. Use `useSafeAreaInsets()`.

### D10. `Dimensions.get('window')` at module load
**Smell.** `const { width } = Dimensions.get('window');` outside a component.
**Why bad.** Doesn't update on rotate, split-screen, or foldable unfold. Use `useWindowDimensions()`.

### D11. Keyboard listeners without cleanup
**Smell.** `Keyboard.addListener('keyboardDidShow', ...)` with no `remove()` on unmount.
**Why bad.** Listener fires on a torn-down screen → crash or memory leak.
```tsx
useEffect(() => {
  const sub = Keyboard.addListener('keyboardDidShow', onShow);
  return () => sub.remove();
}, []);
```

### D12. Calling native modules without platform guard
**Smell.** Direct call to a native-only module on web.
**Why bad.** Throws on first render. Either guard with `Platform.OS !== 'web'` or use a `.web.ts` shim.
```ts
if (Platform.OS !== 'web') Haptics.selectionAsync();
```

### D13. No accessibility on custom touchables
**Smell.** `<Pressable onPress={...}><Icon /></Pressable>` with nothing else.
**Why bad.** Screen readers announce "button" with no purpose. Always set `accessibilityRole` + `accessibilityLabel`.

### D14. `TouchableOpacity` everywhere
**Smell.** `TouchableOpacity` as the default for all buttons.
**Why bad.** Less control, less future-proof; RN docs recommend `Pressable`. Reserve `TouchableOpacity` for trivial cases.

### D15. `console.log` shipped to prod
**Smell.** Debug logs in release builds.
**Why bad.** Slows JS thread, exposes internals. Use `__DEV__` or a tree-shaken logger.

### D16. Synchronous `JSON.parse` of huge payloads
**Smell.** `JSON.parse(bigString)` on the JS thread.
**Why bad.** Blocks render. Stream from disk, parse on a worker, or store structured in SQLite/MMKV.

### D17. `useState` for nav params
**Smell.** Pulling search params into a local `useState` and writing back manually.
**Why bad.** Two sources of truth; back/forward and deep links desync the state. Read `useLocalSearchParams()` directly.

### D18. Modals as toggled siblings
**Smell.** `{open && <MyModal />}` mounted in a screen body.
**Why bad.** Misses native presentation, breaks deep linking, bad gesture handling. Use `<Modal>` for in-screen overlays or `expo-router` modal routes.

### D19. Forgotten splash hide
**Smell.** Called `preventAutoHideAsync()` but never `hideAsync()`.
**Why bad.** App is stuck on splash forever — common on a fonts-loading error path.

### D20. Build profiles with no env separation
**Smell.** Same `EXPO_PUBLIC_API_URL` for dev/preview/prod.
**Why bad.** Production users hit staging; debug logs leak; analytics double-count. Define per-env in EAS.

### D21. Disabling Hermes "for JSI compatibility"
**Smell.** `jsEngine: 'jsc'` with no measured reason.
**Why bad.** Lose Hermes startup, smaller bundle, and required New Architecture support. JSI works on Hermes — that's the point.

### D22. `setTimeout` for animations
**Smell.** `setTimeout(() => setOffset(o + 1), 16)` to "animate" something.
**Why bad.** Runs on the JS thread, drops frames, ignores reduced-motion. Use reanimated.

### D23. Polling for background tasks
**Smell.** `setInterval(syncWithServer, 60_000)` while backgrounded.
**Why bad.** OS suspends your JS within seconds of background. Use `expo-background-fetch` / `expo-task-manager`.

### D24. Permissions on app launch
**Smell.** Asking for camera + location + notifications in the splash flow.
**Why bad.** iOS denies repeat asks; users reject; conversion tanks. Ask the moment the feature is invoked.

### D25. iOS-only or Android-only assumptions in shared code
**Smell.** Code that calls `react-native-haptic-feedback` without guarding web, or assumes `BackHandler` exists everywhere.
**Why bad.** Crashes on web (Expo Web) or other-OS. Use `Platform.OS` or `.ios.tsx` / `.android.tsx` / `.web.tsx`.

### D26. Missing dark mode
**Smell.** Hardcoded `backgroundColor: '#fff'` and `color: '#000'` everywhere.
**Why bad.** Eye-searing for users who default-system-dark; reviewers flag it. Use a theme provider keyed off `useColorScheme()`.

### D27. `useEffect` to fetch when TanStack Query exists
**Smell.** `useEffect(() => { fetch(...).then(setData); }, [id])` with manual loading/error state.
**Why bad.** Reimplements (and gets wrong) cache, dedupe, retry, focus refetch, offline. Use `useQuery`.

### D28. Hardcoded API URL
**Smell.** `const API = 'https://api.acme.com'` inline.
**Why bad.** Can't switch envs without a code change. Use `process.env.EXPO_PUBLIC_*` or `Constants.expoConfig?.extra`.
```ts
// right
const API = process.env.EXPO_PUBLIC_API_URL!;
```

### D29. `react-native-vector-icons` in an Expo project
**Smell.** Installing `react-native-vector-icons` and configuring fonts manually.
**Why bad.** `@expo/vector-icons` already bundles Ionicons / MaterialCommunity / Feather / FontAwesome — no native config, EAS-ready.

### D30. Untyped routes when typed routes are available
**Smell.** `experiments.typedRoutes: false` (or unset) with `<Link href="/posts/42" />` strings.
**Why bad.** Typos compile; refactors silently break. Flip the flag, fix the errors, never look back.

## How to use this file

- **Reader mode.** When the user asks "what's the right way to X in RN/Expo," locate the rule by name and quote rule + reason + example.
- **Reviewer mode.** When the user pastes RN code, scan for D-rules first (most have concrete code shapes to match), then check A/B compliance. Cite by id (e.g. "D2 — inline style in renderItem").
- **Out of scope.** React-general patterns (component design, hook rules, Suspense, RSC) → see `frameworks/react.md`. Bare RN CLI build/eject details intentionally light; this file assumes Expo managed + EAS.
